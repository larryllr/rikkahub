# 宽 API 原生候选：审计与美学交接

更新记录：2026-11-23（北京时间）。本文是给不读取前序对话的审计者的入口，包含期望、当前代码、未证明的行为及验收标准。[构建](BUILD.md) · [改动地图](CHANGE-MAP.md)。候选独立于生产；正式宽 API 1.6.10、官方 Sub2API、Grok、Copilot、桌面启动器、DNS/Tunnel、服务配置及线上数据都不在本项目的写入范围。

## 产品目标

原生 Jetpack Compose 的 RikkaHub 3.3.1 为基座。最大限度保留它的首页、聊天、侧栏、系统明暗、Material 3 Expressive、手势、消息树、文件夹、搜索、标签、助手、记忆、备份、媒体、工具和工作区。不要照搬任何宽 API WebView，也不做第二套聊天。宽 API 的帐号和权限、Web GPT/Work、本机文件及服务端原件、服务端后台与本机工作区，是在上述交互中合流的功能，不是换一张皮。

在源上按四类区分：上游已有、候选新写、需要进一步接入、实际验收。以下描述为代码范围，只有交付核验记录能证明安装或实用性。

## 边界与接口

- 基准线上主域 `https://kuanapi.kuankuan.de5.net`；双域名服务部署关系不变。本候选认证仅用主域，防止出现跨域 bearer 复用；不把备用域名作隐式 fallback。
- 官方 Sub2API API：`/api/v1/settings/public`、`/auth/login`、`/auth/register`、`/auth/login/2fa`、`/auth/send-verify-code`、`/auth/refresh`、`/auth/logout`、`/auth/me`（均在 `/api/v1` 下），用量 `/usage/dashboard/stats`，管理员 `/admin/dashboard/stats` 和 `/admin/groups/all`。
- 宽 API 外置契约：`GET /api/v1/groups/chat`、`POST /api/v1/chat/api-key` 传 `group_id`、`GET /v1/models?kuan_chat=1` 用该组 bearer；管理员的 `GET/PUT /api/v1/admin/settings/chat-groups`；`/v1/chat/completions` 与 `/v1/responses` 携带 `x_kuanapi_chat` 明确区分模式。不会创建影子账号、维护模型白名单或修改 Sub2API 核心。
- `POST /api/v1/kuan/chat-assets` 原始二进制带 `X-Kuan-Filename`，仅在成功回执已校验后把引用放进推理请求。服务器保留期并不等于永久存储，需测试失效和本机原件重新读取；较大批量不要在内存一次拼 Base64。
- `POST/GET/DELETE /api/v1/kuan/chat-jobs` 和 `POST /{id}/cancel`：单次调用固定账号、组、模型、会话、锚点和回复 ID。后端收到并持久化才出现接单文案。重连从事件 0 回放或按内存游标继续，同一节点覆盖未完成尝试；核对全部事件和成功终止后，先写原会话再确认领取。未知提交结果不提交第二个任务。需要重点挑战“用户切换分支”“进程在落盘和确认间退出”“切组旧 job”“迟到数据”。
- 持久化：RikkaHub Room / DataStore / app 私有文件与备份；宽 API token 单独放 Keystore 加密的 no-backup 文件，不在模型配置或业务日志输出。当前预览一个 Android 私有资料只绑定一个宽 API 账号，不承诺共享设备多账号可见性。登出保留原持有者的本机数据，不是擦除内容。服务端 Session 管理与 BYOK 独立。
- 供应链：由源码上游 PRoot/SSH/手机 Web/媒体资源保留；审计构建依赖、第三方条款、运行环境权限、授权边界、共享目录和备份泄漏。不在任何交付件放生产环境、账号、访问 token、API Key、签名私钥或私人聊天。

## 审计方法

1. 以构建文件、Git 基准提交、ARM64/x86_64 APK 的证书 / 包名 / 版本 / 摘要为起点。检查正式包和候选是否共存；不能用旧包的截图、HTTP 200 或 stub 数据证明新包有效。
2. 用独立 fixtures 或明确授权的非生产普通账号和管理员测试；不接真实用户数据。检查增删授权目录、动态新模型、未授权模型不可用、登录/注册/TOTP/过期/重登。两个分组同一 model ID、不同分组同时完成，不能串组与隐式补发。
3. 测文字/表格/LaTeX/代码/Mermaid/链接/动态题目、5 秒首字与长输出卡顿。分别取响应首事件、首可见内容和完整结束时间，统计至少多个样本，别拿 DOM/HTTP 或单个时间切片替代。
4. 断 Wi-Fi、后台、强杀、恢复、拒绝和停止；查看服务端任务 ID 与本地 reply ID，全成功只确认一次。检查客户端生成从直连断掉时不显示“服务器已接单”。确认不跨组、不重复计费、不写错分支。
5. 以合成 PDF（含扫描件）、相机图、同名不同二进制附件、200 个小文件、较大代码文件和多轮原件追问验收，不以纯文本提示替代原文件。测试文件名特殊字符、.py 原后缀、失效资源、HTTPS、生成件出入库、保存到相册和离线打开。
6. 旧历史迁移需要合法的用户导出/云端可读副本；验证 owner、格式版本、zip 上限及路径安全、分支/附件稳定 ID，合并后幂等可预览且可回退。现候选未交付此步骤，审计不能误标通过。
7. 审计原生界面时用 RikkaHub 3.3.1 同设备邻放参考。至少查 360dp 窄屏/高字体、横屏和平板，系统深浅色、键盘和返回手势、原生滑块触控、头像、模型列表密度与底部选区、长内容滑动、静态和动效连贯。优先缩减突兀新操作，不另画主页，不做无功能的假按钮。
8. 审核只读与权限：管理员二次确认、账号失效、未加密或 LAN embedded web、日志、备份、意外跨域、XSS/Markdown URL、客户端模型工具和用户知情。不要在生产提交写入用例；用模拟服务重放。
9. 再验收安装来源、下载续交互、相同证书和更新后会话仍在，拒绝篡改包/错误哈希/回退版本/错误 ABI。没有专用清单和两版包即未验收在线升级。

此文件与代码一起更新；任何从“未验收”变为“通过”的项必须附上设备、版本、可复现实验输入及实际证据。不要把这份审计要求放到应用界面。
